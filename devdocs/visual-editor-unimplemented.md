# ビジュアルエディター未実装項目一覧

更新日: 2026-09-30

ループ・文字列補間・ドリルダウンの改善後（`4d2e03f`）に確認した、
ビジュアルエディターの編集機能の不足を記録する。
設計全体は [06-visual-editor.md](06-visual-editor.md) を参照。

構文を表示できることと、グラフ上だけで作成・変更・削除できることは別である。
以下は実装を照合して確認した不足であり、全構文の表示・編集を網羅的に検証した結果ではない。

## 1. 通常のリテラルのソース反映

- [ ] 通常の数値・文字列の編集をソースへ反映する。
- [ ] 通常のリテラルと補間文字列の編集動作を統一する。

現状、通常の数値・文字列には編集欄があるが、変更はグラフ内だけに保持される。
補間の文字列断片・書式はソースへ反映されるため、動作が不揃いになっている。

関連: `src/webview/rf/LiteralInput.tsx`、`src/webview/rf/main.tsx`、
`src/graphInterpolation.ts`

## 2. 値・式・参照先の差し替え

- [ ] 値や穴から、別の式へ変更する共通の編集入口を用意する。
- [ ] 参照先を別の変数・関数へ変更できるようにする。
- [ ] リテラルから呼び出し式などへ変更し、式を組み立てられるようにする。

例: `a` を `b` にする、`0` を `f(x)` にする、穴へ別の式を入れる。
宣言名を変更して参照を追従させるリネームとは別の操作である。
条件式・引数・戻り値・代入値・補間値で共通に使える仕組みが必要。

関連: `src/protocol.ts`、`src/webview/labels.ts`、`src/webview/rf/NameInput.tsx`

## 3. 真偽値・nil の編集

- [ ] `true^` / `false^` を切り替えられるようにする。
- [ ] `nil^` を別の値・式へ変更できるようにする。

補間要素の追加で生成する `{nil^}` にも、追加後に値を変更する入口が必要。
項目2の共通編集に含めて扱う。

## 4. 条件分岐・パターン分岐の構造編集

- [ ] 分岐の枝を追加・削除できるようにする。
- [ ] else の枝を追加できるようにする。
- [ ] パターンの構造を変更できるようにする。

既存の条件や各枝の表示、枝の本体への文追加とは別に、分岐構造そのものの編集が必要。

## 5. ループの構成変更

- [ ] `pre^` / `first^` / `main^` / `last^` / `epilog^` 等の節自体を追加・削除できるようにする。
- [ ] while / until / 範囲形式など、ループ形式を切り替えられるようにする。

本体や既存の節の中へ文を追加する仕組みはあるが、節そのものの構成変更は未対応。

## 6. 構文の新規作成入口

文の追加メニューは一部のテンプレートに限られている。
既存の構文の内部を編集できる場合でも、その構文を新しく作る入口が不足している。

- [ ] 呼び出し文・再代入を追加できるようにする。
- [ ] `with^` を追加できるようにする。
- [ ] 例外処理を作成できるようにする。
- [ ] `yield^` / `await^` を作成できるようにする。
- [ ] 型・列挙・エラー定義を作成できるようにする。
- [ ] module / import / require 等の作成入口を整備する。
- [ ] その他の構文についても、追加候補と作成可能な場所を照合する。

関連: `src/graphStatements.ts` の `statementTemplates`、
`src/graphLists.ts` の `listTemplates`

## 7. 汎用の削除操作

- [ ] 文を削除できるようにする。
- [ ] 引数・メンバ等のリスト要素を削除できるようにする。
- [ ] 分岐の枝・ループ節にも共通の削除操作を適用する。

追加・並べ替え・文の無効化はあるが、汎用の削除操作はない。
無効化と削除は別の操作として扱う。

関連: `src/protocol.ts`、`src/graphStatementEditor.ts`、`src/graphReorder.ts`

## 8. 演算子の編集範囲

- [ ] 単項演算子の変更操作を用意する。
- [ ] 算術・比較・and/or 以外の演算子について、変更候補と操作を整備する。

現状、変更候補があるのは主に算術・比較・and/or。
表示されても変更できない演算子があるため、表示と編集の対応を確認する。

関連: `src/graphLists.ts` の `operatorSites`、
`src/webview/operatorExpression.ts`

## 9. モジュール情報・コメントの編集

- [ ] module / import / require のモジュール名・読み込み先などを編集できるようにする。
- [ ] コメント本文を編集できるようにする。

表示はあるが、これらの内容を変更する専用UIはない。

## 10. アノテーションの表示・編集

- [ ] アノテーションを付与先との関係が分かる形で表示する。
- [ ] アノテーションを追加・削除できるようにする。
- [ ] アノテーション名と引数を編集できるようにする。
- [ ] 引数の追加・削除と値・式の共通編集に対応する。
- [ ] 通常表示・折りたたみ・ドリルダウンでの扱いを確認する。

ここで扱うのは言語のアノテーション（ASTの `annotation`）であり、
既存の型注釈編集とは別の機能である。
本体のASTには名前と引数（`name` / `members`）があるが、
ビジュアルエディターにはこの構文専用の表示・編集処理がない。
汎用描画で現れる可能性と、アノテーションとして対応できていることを区別し、
付与先との関係も含めて確認する。

## 共通化・実装の優先順案

1. **値・式の共通編集**: リテラルのソース反映、真偽値切替、参照先変更、式の置換・組み立て。
2. **要素の共通追加・削除**: 文、引数、メンバ、分岐の枝、ループ節など。
3. **構文固有の設定**: ループ形式、修飾子、読み込み先など。既存の書式編集も共通UIとの整合を保つ。

特に「穴やインライン値を別の式へ変更する共通の入口」を先に整えると、
構文ごとに専用の編集処理を増やさず、多くの編集箇所をまとめて対応できる。

## 網羅性の確認タスク

- [ ] ASTの全種類について、通常表示・折りたたみ・ドリルダウンの見た目を確認する。
- [ ] 修飾子や構文の組み合わせについても確認する。
- [ ] 各構文の「表示」「新規作成」「内容変更」「構造変更」「削除」を別々に確認する。
- [ ] 編集欄の有無だけでなく、ソース反映と編集後の再表示まで確認する。

この確認が完了するまでは、全構文の見た目・編集機能を網羅したとはしない。

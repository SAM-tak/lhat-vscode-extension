# ビジュアルエディター未実装項目一覧

更新日: 2026-10-30

ループ・文字列補間・ドリルダウンの改善後（`4d2e03f`）に確認した、
ビジュアルエディターの編集機能の不足を記録する。
設計全体は [06-visual-editor.md](06-visual-editor.md) を参照。

構文を表示できることと、グラフ上だけで作成・変更・削除できることは別である。
以下は実装を照合して確認した不足であり、全構文の表示・編集を網羅的に検証した結果ではない。

## 1. 通常のリテラルのソース反映

- [x] 通常の数値・文字列の編集をソースへ反映する。
- [x] 通常のリテラルと補間文字列の編集動作を統一する。

通常の数値・文字列も Enter / フォーカス離脱で未保存の文書へ反映する。
補間の文字列断片・書式と同様に、バージョンと AST の位置を検証した WorkspaceEdit を使う。
ブラウザーで入力→文書編集→再表示、Escape、古いバージョンの拒否を確認済み。
構造メニューで raw / エスケープ付き文字列を切り替えられる。raw で表現可能な内容なら値の編集後も raw の表記を保つ。
文字列と補間の断片にはエスケープ表記の編集も用意する。UTF-8として読めないバイトを含む値も、ソース表記を保って作成・変更できる。先頭末尾の空白と空文字も保持する。行末形式への変更は、後続のコメントや閉じ記号を取り込まない場所でだけ提示し、CRLFも維持する。通常・折りたたみ・ドリルダウンのSVGに値と表記が残ること、実サーバーを通した作成・変更・削除と再表示を確認した。

関連: `src/webview/rf/LiteralInput.tsx`、`src/webview/rf/main.tsx`、
`src/graphInterpolation.ts`

## 2. 値・式・参照先の差し替え

- [x] 値や穴から、別の式へ変更する共通の編集入口を用意する。
- [x] 参照先を別の変数・関数へ変更できるようにする。
- [x] リテラルから呼び出し式などへ変更し、式を組み立てられるようにする。

値ノードの鉛筆ボタンから、値・参照の置換と呼び出し・添字・加算・単項式への組み立てが可能。
ブラウザーで `0` → `fn` → `(fn)(nil^)` の作成と再表示を検証。
参照欄は `self^.count` / `Item.new` / `items.length^` / `values.0` のようなメンバー参照を受け付ける。
参照名を入力した場合は完全一致を先頭に表示し、`library.code` が `examples.referenceLibrary.code` の部分一致に紛れないようにする。
式をメンバー参照で包み、メンバーキーを変更する編集も追加した。
式の結果をレシーバーにするメンバー参照は、レシーバーとキーをそれぞれ編集できる。再代入の添字付き左辺も式ノードとして表示し、添字と参照先を編集できる。
require 式の作成も共通メニューから行い、読み込み先をインライン入力で変更できる。
nil でないかを調べる後置 `value?` も共通メニューから作成できる。演算子を値の後ろに表示し、内部の値の編集と式全体の置換も実サーバー・ブラウザーで確認した。
補間の穴の中でも、式の外側にある括弧を穴の範囲内で補ってから置換する。補間全体を文字列として読む字句処理に妨げられず、添字式をフォールバック等で包める。
全構文の作成・変更・削除の網羅性は引き続き検証する。
単独の呼び出し文では文として成立する式だけを変更候補にする。tryやフォールバックの内側でも必要な呼び出しを保ち、呼び出し先と引数は個別に編集する。関数の暗黙の戻り値には通常の式候補を残す。フォールバック付き呼び出しの表示行にも文全体の削除ボタンを付け、空の文書からの作成・引数変更・削除をUIで検証した。

例: `a` を `b` にする、`0` を `f(x)` にする、穴へ別の式を入れる。
宣言名を変更して参照を追従させるリネームとは別の操作である。
宣言名のリネームでは、言語サーバーが同一 URI・範囲・内容の編集を重複して返した場合も一度だけ適用する。`with^` の束縛名を変更しても周囲の代入構文を壊さない。
条件式・引数・戻り値・代入値・補間値で共通に使える仕組みが必要。

## 4. 条件分岐・パターン分岐の構造編集

- [x] 分岐の枝を追加・削除できるようにする。
- [x] else の枝を追加できるようにする。
- [x] パターンの構造を変更できるようにする。

通常の if 文・式に構造編集メニューを追加。条件付きの枝を追加・削除でき、先頭を削除すると次の枝を昇格する。
if 式の必須 else は削除候補に出さない。実サーバーで再解析し、UI操作→再表示も確認した。
パターン分岐は文・式の作成、枝の追加・削除、数値・文字列・範囲・複数候補・型パターンへの変更に対応。

選択肢の値と範囲の両端は共通入力で編集でき、選択肢の＋と削除にも対応する。最後の1件は枝の構造を保つため削除候補に出さない。
照合する値の名前付き束縛と、名前を付けない形式も切り替えられる。
型パターンの型は構造メニューで変更でき、テーブル型のメンバー追加・名前と型の編集・削除にも共通部品を使う。選択肢の ＋ から型・範囲パターンも追加できる。
入れ子のテーブル値を使うパターンも、共通の式・リスト編集で作成し、内部の値と名前の変更・削除・再追加を行える。空の文書からUIだけで構築し、型パターンとテーブル値のパターンが期待するASTに一致することを実サーバーとブラウザーで確認した。

## 5. ループの構成変更

- [x] `pre^` / `first^` / `main^` / `last^` / `epilog^` 等の節自体を追加・削除できるようにする。
- [x] while / until / 範囲形式など、ループ形式を切り替えられるようにする。

構造編集メニューで prolog / pre / first / main / last / epilog / finally の追加と、明示節の削除に対応。
全7種類の節について、空のループへの追加→本体の文の追加→共通の × での削除を実サーバーとブラウザーで検証した。
暗黙の main に文がある場合は明示化して保持する。唯一の main は内容を空にする操作として表示する。
回数指定・無限・while・until・範囲形式への切り替えを追加。本文・節はソースをそのまま保持する。
既存の for の変数初期化・next は while/until 間で維持し、範囲からの切り替えでは変数を維持する。
条件付き for は変数の新規宣言と既存変数への代入を切り替えられ、next の更新処理も追加・削除できる。
範囲形式は昇順・降順と刻み幅の指定・削除に対応。これらの操作でも括弧付き初期値と本文・節を保持する。
イテレーター形式も作成でき、値の名前は既存のリネーム入力で変更する。キーを受け取る・省く操作にも対応する。
解析時の単一名の仮束縛は画面では1つの宣言名として表示し、値の差し替えやカンマリスト追加の対象にはしない。
空の明示的な main 節にも文を追加できる。本体の波括弧直後に付くコメントも構造メニューから作成できる。
不適合な条件・範囲は既定値に置き換えるため、変更後に入力欄で値を設定する。
回数指定・無限・while / until・範囲・1変数 / 2変数イテレーターを含む9種類の初期形式で、表示される全切替候補を実サーバーで再解析した。本体と pre / main / last / epilog / finally のソースが変わらないことを確認した。
break・nextの構造メニューで、現在のcallable内のループ段数から離脱先を選べる。互いの切り替え、別名や角括弧表記からの変更、空の文書からの作成・再表示・削除を確認した。

## 6. 構文の新規作成入口

文の追加メニューに呼び出し・再代入・with・catch付きブロック・定義系・読み込み系を追加。
手続き内では yield / await を選べる。module は未宣言のファイル先頭でのみ選べる。
yield / awaitは手続きの本文内の式としても作成・差し替えでき、受信した値や委譲先の結果を束縛できる。別の関数や既定引数の中には中断する候補を出さない。yieldは構造メニューでphantom形式へ切り替え、`_yield^`の見出し全体と送信値リストを保つ。空の送信リストへの再追加、式を内側の値へ戻す操作もUIで確認した。
初期値や参照先には編集用の仮値を置くため、作成だけで型検査が通るとは限らない。
関数・手続きの引数追加から可変長引数を末尾に追加できる。重複と後続引数の追加は拒否し、型は既存の型編集で変更する。
本文の `...` 参照と添字アクセスも共通の式編集で作成する。return の直後で別の文として解析されないよう括弧で包む。
関数・手続きは構造メニューから `template^` を追加・解除でき、見出しにも表示する。AST範囲の外にある修飾子を含めて式の置換・要素削除・並べ替えを行う。
`mutable^self^` と `fresh^` は、関数本体と注釈内のシグネチャの双方で切り替える。fresh の戻り値がタプルにならないよう型の追加・変更候補を制限し、型注釈の削除では修飾子と矢印も取り除く。入れ子の引数シグネチャにある矢印とは区別する。
finally内とその子ブロックでは、言語が禁止するreturnを文追加候補に出さない。その中で定義した別の関数・手続きにはこの制限を引き継がない。
例外処理は既存のブロック・関数・if・with・ループにも追加できる。型を指定するcatchと末尾のcatch-allを追加し、修飾付きエラー名・選択肢をメニュー内の入力で変更する。catch-allの重複や、その後ろへの分岐追加は許可しない。catch・finallyは共通の×で削除でき、空のcatchの範囲が次の節へ重なるASTでも次の節を保持する。ループのmain・先行節の変更もcatchの境界で区切る。
読み込み先は項目9のインライン編集、構文固有の設定は構造メニューで変更する。

- [x] 呼び出し文・再代入を追加できるようにする。
- [x] `with^` を追加できるようにする。
- [x] 例外処理を作成できるようにする。
- [x] `yield^` / `await^` を作成できるようにする。
- [x] 型・列挙・エラー定義を作成できるようにする。
- [x] module / import / require 等の作成入口を整備する。
- [ ] その他の構文についても、追加候補と作成可能な場所を照合する。

`for^ ... do^:` は共通の式メニューから作成でき、束縛名・初期値・結果の式を既存の入力で編集する。外側のローカル束縛は構造メニューから追加・削除でき、`for^ ... for^ ...` と駆動節を共有する形も構築できる。生成する名前は文書内の既存名を避け、元の参照を捕捉しない。式・文の判定は内側の駆動節へ従い、文の連鎖には実行線をつなぐ。ブラウザーで空の文書からの作成と AST 一致、複数段の追加・削除後の編集継続を確認した。その他の構文の網羅性は引き続き照合する。
`typeof^`・box / constbox・型の値は共通の式メニューから作成する。型取得とboxの内側の値を編集でき、内側の値に戻す操作も用意する。boxの変更可能・読み取り専用も構造メニューで切り替える。型の値は `number^` などを書き、既存の型構造メニューで変更する。
末尾の呼び出し引数は展開形式へ変更でき、展開中も内部の値・タプル要素を編集する。展開済み引数の後ろへの追加は表示せず、展開を解除すると再び追加できる。
`id^` の名前値はインライン入力で編集し、変数の宣言名を変更しない。明示的なスコープ参照は参照名の入力と、単位・相対参照・距離の構造メニューで作成・変更する。
delegate は定義の要素追加から1件だけ作成できる。名前または `self^.名前` へ参照先を変更し、共通の削除で取り除く。値や呼び出しへの置換は許可しない。
型ラベルの構造メニューからタプル・交差・関数・コルーチン・型記述子の適用型を作成できる。内側の型を変更する候補は型全体の変更後のプレビューを表示する。タプル・適用型の要素追加・削除も同じ入口を使い、括弧と隣接コメントを保持する。
注釈内のテーブル型のメンバー名は構造メニュー内の入力で変更し、個数は共通の追加・削除で編集する。関数・手続き型の入出力も追加・削除でき、最後の戻り値を消すと矢印も取り除く。可変長引数は末尾に1件だけ追加でき、削除すると通常の追加へ戻る。
型のself節内にも位置要素と索引型を追加できる。位置の個数指定・無制限への切り替え・削除に通常のテーブル型と同じ処理を使い、索引型は節ごとに1件に限定する。空の文書からのUI構築・ASTと字句列の一致・変更後の再表示・削除を確認した。
コルーチン型は関数・手続き・種別任意を切り替えられる。受信・中断・終了の型の指定、省略、任意の型と終了しない指定にも対応し、他の指定と隣接コメントを保持する。空の文書からのUI作成・AST一致と、入れ子の関数型を含む各形式の再解析を検証した。
その他の構文と修飾子の組み合わせは引き続き言語側の AST 定義と照合する。
varの構造メニューで、型を保ったまま宣言先を名前またはメンバーへのパスへ変更できる。`=`による新規導入と`:=`による既存メンバーへの代入許可を切り替え、後者は見出しにも表示する。letはメンバーへのパスを許さず、varからletへの変更時は`:=`も`=`に直す。引用されたメンバー名・複数の宣言先・型と隣接コメントの保持を実サーバーで検証し、UI作成・変更・削除とAST・字句列の一致を確認した。

比較・論理・フォールバック・ビット演算・ベクトル積も共通の式メニューから作成できる。
引数とエラーペイロードには既定値を追加・削除でき、その値は既存の入力ノードで編集する。
def にはコンストラクターを作成できる。メンバー関数には self^ 引数を追加でき、既存引数があっても必ず先頭へ入れる。
通常のテーブル要素は名前のキーを文字列・数値キーへ変更でき、入力ノードでキーを編集する。名前に戻せる文字列にはその変更候補も表示する。
計算キーは共通の式メニューで参照・演算・呼び出しへ変更でき、値の型も既存の型ラベルで編集できる。括弧付きキーを名前へ戻しても値と隣接要素を保つ。
式だけの関数本体では、構造メニューで明示的な return と暗黙の戻り値を切り替えられる。
複数文の本体や手続きでは、return の削除によって意味が変わるためこの切り替えを表示しない。

関連: `src/graphStatements.ts` の `statementTemplates`、
`src/graphLists.ts` の `listTemplates`

## 7. 汎用の削除操作

- [x] 文を削除できるようにする。
- [x] 引数・メンバ等のリスト要素を削除できるようにする。
- [x] 分岐の枝・ループ節にも共通の削除操作を適用する。

文と通常のカンマ区切りリスト要素に削除ボタンを追加。文書バージョンを検証してソースへ反映する。
呼び出し結果の展開を含まない複数束縛・並列代入では、名前または値を削除すると対応するペアも同時に削除する。
括弧付きの右辺も括弧ごと取り除き、残りのペアと代入演算子を保つ。
隣接要素のコメントと区切りを保持する。呼び出し結果を受ける束縛の削除は、その位置を `_^` に変え、後続の戻り値の位置と呼び出しの評価回数を保つ。名前を再入力して束縛に戻すこともできる。
複合代入では右辺に呼び出しを含む場合も対応するペアを削除できる。添字と for の焦点の最後の要素は保護し、最後の更新処理を消すと next も取り除く。
入れ子のタプル型の要素は型ラベルの構造メニューからも削除できる。残りが1つなら括弧付きの型へ戻る。適用型の最後の引数は保護する。
分岐・パターン分岐の枝と、ループの各節・next にも共通の × を表示し、構造メニューと同じ処理で削除する。
main は独立したボックスを増やさず、小さな見出しと × を表示する。空にした後も既存の ＋ で本体へ文を追加できる。
焦点付き条件分岐で唯一の枝を削除するときは焦点も取り除き、不完全な for ヘッダーを残さない。式の必須 else は削除候補に出さない。
明示した戻り値型は共通の削除ボタンで1件ずつ削除できる。最後の型を消すと矢印も取り除き、推論へ戻す。戻り値本体と隣接コメントは保つ。
個別の型や戻り値の型全体が括弧で包まれている場合も、残りの型の括弧を保つ。
無効化と削除は別の操作として扱う。
式変更・構造編集・削除はボックス外側の一列に並べる。実際のポインター操作で各ボタンを個別に押せることと、値の入力欄を遮らないことを検証した。

関連: `src/protocol.ts`、`src/graphStatementEditor.ts`、`src/graphReorder.ts`

## 8. 演算子の編集範囲

- [x] 単項演算子の変更操作を用意する。
- [x] 算術・比較・and/or 以外の演算子について、変更候補と操作を整備する。

単項の `-` / `!` / `bitnot^` を演算子メニューから変更できる。
二項は算術・連結・三方比較・等値/大小比較・同一性・ビット演算・フォールバック・ベクトル積の候補を追加した。
言語側の演算子定義と照合し、表示する全候補を実サーバーで再解析した。無効な `==` は候補から除き、書かれた左右の値や型を保つことを確認した。単項演算と後置の nil 判定は内側の値へ戻すこともできる。

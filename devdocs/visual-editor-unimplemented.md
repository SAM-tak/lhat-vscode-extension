# ビジュアルエディター未実装項目一覧

更新日: 2026-10-29

ループ・文字列補間・ドリルダウンの改善後（`4d2e03f`）に確認した、
ビジュアルエディターの編集機能の不足を記録する。
設計全体は [06-visual-editor.md](06-visual-editor.md) を参照。

構文を表示できることと、グラフ上だけで作成・変更・削除できることは別である。
以下は実装を照合して確認した不足であり、全構文の表示・編集を網羅的に検証した結果ではない。

## 1. 通常のリテラルのソース反映

- [x] 通常の数値・文字列の編集をソースへ反映する。
- [x] 通常のリテラルと補間文字列の編集動作を統一する。

通常の数値・文字列も Enter / フォーカス離脱で未保存の文書へ反映する。
補間の文字列断片・書式と同様に、バージョンと AST の位置を検証した WorkspaceEdit を使う。
ブラウザーで入力→文書編集→再表示、Escape、古いバージョンの拒否を確認済み。
構造メニューで raw / エスケープ付き文字列を切り替えられる。raw で表現可能な内容なら値の編集後も raw の表記を保つ。

関連: `src/webview/rf/LiteralInput.tsx`、`src/webview/rf/main.tsx`、
`src/graphInterpolation.ts`

## 2. 値・式・参照先の差し替え

- [x] 値や穴から、別の式へ変更する共通の編集入口を用意する。
- [x] 参照先を別の変数・関数へ変更できるようにする。
- [x] リテラルから呼び出し式などへ変更し、式を組み立てられるようにする。

値ノードの鉛筆ボタンから、値・参照の置換と呼び出し・添字・加算・単項式への組み立てが可能。
ブラウザーで `0` → `fn` → `(fn)(nil^)` の作成と再表示を検証。
参照欄は `self^.count` / `Item.new` / `items.length^` / `values.0` のようなメンバー参照を受け付ける。
参照名を入力した場合は完全一致を先頭に表示し、`library.code` が `examples.referenceLibrary.code` の部分一致に紛れないようにする。
式をメンバー参照で包み、メンバーキーを変更する編集も追加した。
式の結果をレシーバーにするメンバー参照は、レシーバーとキーをそれぞれ編集できる。再代入の添字付き左辺も式ノードとして表示し、添字と参照先を編集できる。
require 式の作成も共通メニューから行い、読み込み先をインライン入力で変更できる。
nil でないかを調べる後置 `value?` も共通メニューから作成できる。演算子を値の後ろに表示し、内部の値の編集と式全体の置換も実サーバー・ブラウザーで確認した。
補間の穴の中でも、式の外側にある括弧を穴の範囲内で補ってから置換する。補間全体を文字列として読む字句処理に妨げられず、添字式をフォールバック等で包める。
全構文の作成・変更・削除の網羅性は引き続き検証する。

例: `a` を `b` にする、`0` を `f(x)` にする、穴へ別の式を入れる。
宣言名を変更して参照を追従させるリネームとは別の操作である。
宣言名のリネームでは、言語サーバーが同一 URI・範囲・内容の編集を重複して返した場合も一度だけ適用する。`with^` の束縛名を変更しても周囲の代入構文を壊さない。
条件式・引数・戻り値・代入値・補間値で共通に使える仕組みが必要。

関連: `src/protocol.ts`、`src/webview/labels.ts`、`src/webview/rf/NameInput.tsx`

## 3. 真偽値・nil の編集

- [x] `true^` / `false^` を切り替えられるようにする。
- [x] `nil^` を別の値・式へ変更できるようにする。

共通の式メニューで切り替える。ブラウザーで `true^` → `false^` → `nil^` → 数値の編集と実サーバーによる再表示を確認する。
補間要素の追加で生成する `{nil^}` も項目2の共通編集に含めて扱う。

## 4. 条件分岐・パターン分岐の構造編集

- [x] 分岐の枝を追加・削除できるようにする。
- [x] else の枝を追加できるようにする。
- [x] パターンの構造を変更できるようにする。

通常の if 文・式に構造編集メニューを追加。条件付きの枝を追加・削除でき、先頭を削除すると次の枝を昇格する。
if 式の必須 else は削除候補に出さない。実サーバーで再解析し、UI操作→再表示も確認した。
パターン分岐は文・式の作成、枝の追加・削除、数値・文字列・範囲・複数候補・型パターンへの変更に対応。
解析時に生成された焦点との比較式は表示・式編集の対象から外し、書かれたパターンだけを表示する。
選択肢の値と範囲の両端は共通入力で編集でき、選択肢の＋と削除にも対応する。最後の1件は枝の構造を保つため削除候補に出さない。
照合する値の名前付き束縛と、名前を付けない形式も切り替えられる。
型パターンの型は構造メニューで変更でき、テーブル型のメンバー追加・名前と型の編集・削除にも共通部品を使う。選択肢の ＋ から型・範囲パターンも追加できる。
入れ子のテーブル値を使うパターンも、共通の式・リスト編集で作成し、内部の値と名前の変更・削除・再追加を行える。空の文書からUIだけで構築し、型パターンとテーブル値のパターンが期待するASTに一致することを実サーバーとブラウザーで確認した。

## 5. ループの構成変更

- [x] `pre^` / `first^` / `main^` / `last^` / `epilog^` 等の節自体を追加・削除できるようにする。
- [x] while / until / 範囲形式など、ループ形式を切り替えられるようにする。

構造編集メニューで prolog / pre / first / main / last / epilog / finally の追加と、明示節の削除に対応。
全7種類の節について、空のループへの追加→本体の文の追加→共通の × での削除を実サーバーとブラウザーで検証した。
暗黙の main に文がある場合は明示化して保持する。唯一の main は内容を空にする操作として表示する。
回数指定・無限・while・until・範囲形式への切り替えを追加。本文・節はソースをそのまま保持する。
既存の for の変数初期化・next は while/until 間で維持し、範囲からの切り替えでは変数を維持する。
条件付き for は変数の新規宣言と既存変数への代入を切り替えられ、next の更新処理も追加・削除できる。
範囲形式は昇順・降順と刻み幅の指定・削除に対応。これらの操作でも括弧付き初期値と本文・節を保持する。
イテレーター形式も作成でき、値の名前は既存のリネーム入力で変更する。キーを受け取る・省く操作にも対応する。
解析時の単一名の仮束縛は画面では1つの宣言名として表示し、値の差し替えやカンマリスト追加の対象にはしない。
空の明示的な main 節にも文を追加できる。本体の波括弧直後に付くコメントも構造メニューから作成できる。
不適合な条件・範囲は既定値に置き換えるため、変更後に入力欄で値を設定する。
回数指定・無限・while / until・範囲・1変数 / 2変数イテレーターを含む9種類の初期形式で、表示される全切替候補を実サーバーで再解析した。本体と pre / main / last / epilog / finally のソースが変わらないことを確認した。

## 6. 構文の新規作成入口

文の追加メニューに呼び出し・再代入・with・catch付きブロック・定義系・読み込み系を追加。
手続き内では yield / await を選べる。module は未宣言のファイル先頭でのみ選べる。
初期値や参照先には編集用の仮値を置くため、作成だけで型検査が通るとは限らない。
関数・手続きの引数追加から可変長引数を末尾に追加できる。重複と後続引数の追加は拒否し、型は既存の型編集で変更する。
本文の `...` 参照と添字アクセスも共通の式編集で作成する。return の直後で別の文として解析されないよう括弧で包む。
読み込み先は項目9のインライン編集、構文固有の設定は構造メニューで変更する。

- [x] 呼び出し文・再代入を追加できるようにする。
- [x] `with^` を追加できるようにする。
- [x] 例外処理を作成できるようにする。
- [x] `yield^` / `await^` を作成できるようにする。
- [x] 型・列挙・エラー定義を作成できるようにする。
- [x] module / import / require 等の作成入口を整備する。
- [ ] その他の構文についても、追加候補と作成可能な場所を照合する。

`for^ ... do^:` は共通の式メニューから作成でき、束縛名・初期値・結果の式を既存の入力で編集する。外側のローカル束縛は構造メニューから追加・削除でき、`for^ ... for^ ...` と駆動節を共有する形も構築できる。生成する名前は文書内の既存名を避け、元の参照を捕捉しない。式・文の判定は内側の駆動節へ従い、文の連鎖には実行線をつなぐ。ブラウザーで空の文書からの作成と AST 一致、複数段の追加・削除後の編集継続を確認した。その他の構文の網羅性は引き続き照合する。言語側の AST 定義との再照合では、`typeof^`・`type^` の値・box / constbox・末尾引数の展開・`id^` の名前値・明示的なスコープ参照、delegate メンバー、型適用とコルーチン型の作成・編集入口を追加で確認する必要がある。

比較・論理・フォールバック・ビット演算・ベクトル積も共通の式メニューから作成できる。
引数とエラーペイロードには既定値を追加・削除でき、その値は既存の入力ノードで編集する。
def にはコンストラクターを作成できる。メンバー関数には self^ 引数を追加でき、既存引数があっても必ず先頭へ入れる。
通常のテーブル要素は名前のキーを文字列・数値キーへ変更でき、入力ノードでキーを編集する。名前に戻せる文字列にはその変更候補も表示する。
計算キーは共通の式メニューで参照・演算・呼び出しへ変更でき、値の型も既存の型ラベルで編集できる。括弧付きキーを名前へ戻しても値と隣接要素を保つ。
式だけの関数本体では、構造メニューで明示的な return と暗黙の戻り値を切り替えられる。
複数文の本体や手続きでは、return の削除によって意味が変わるためこの切り替えを表示しない。

関連: `src/graphStatements.ts` の `statementTemplates`、
`src/graphLists.ts` の `listTemplates`

## 7. 汎用の削除操作

- [x] 文を削除できるようにする。
- [ ] 引数・メンバ等のリスト要素を削除できるようにする。
- [x] 分岐の枝・ループ節にも共通の削除操作を適用する。

文と通常のカンマ区切りリスト要素に削除ボタンを追加。文書バージョンを検証してソースへ反映する。
呼び出し結果の展開を含まない複数束縛・並列代入では、名前または値を削除すると対応するペアも同時に削除する。
括弧付きの右辺も括弧ごと取り除き、残りのペアと代入演算子を保つ。
隣接要素のコメントと区切りを保持する。呼び出し結果を受ける束縛の削除は、その位置を `_^` に変え、後続の戻り値の位置と呼び出しの評価回数を保つ。名前を再入力して束縛に戻すこともできる。
複合代入では右辺に呼び出しを含む場合も対応するペアを削除できる。添字と for の焦点の最後の要素は保護し、最後の更新処理を消すと next も取り除く。
入れ子のタプル型内部の要素削除は引き続き確認・対応が必要。
分岐・パターン分岐の枝と、ループの各節・next にも共通の × を表示し、構造メニューと同じ処理で削除する。
main は独立したボックスを増やさず、小さな見出しと × を表示する。空にした後も既存の ＋ で本体へ文を追加できる。
焦点付き条件分岐で唯一の枝を削除するときは焦点も取り除き、不完全な for ヘッダーを残さない。式の必須 else は削除候補に出さない。
明示した戻り値型は共通の削除ボタンで1件ずつ削除できる。最後の型を消すと矢印も取り除き、推論へ戻す。戻り値本体と隣接コメントは保つ。
個別の型や戻り値の型全体が括弧で包まれている場合も、残りの型の括弧を保つ。
無効化と削除は別の操作として扱う。
式変更・構造編集・削除はボックス外側の一列に並べる。実際のポインター操作で各ボタンを個別に押せることと、値の入力欄を遮らないことを検証した。

関連: `src/protocol.ts`、`src/graphStatementEditor.ts`、`src/graphReorder.ts`

## 8. 演算子の編集範囲

- [x] 単項演算子の変更操作を用意する。
- [ ] 算術・比較・and/or 以外の演算子について、変更候補と操作を整備する。

単項の `-` / `!` / `bitnot^` を演算子メニューから変更できる。
二項は算術・連結・三方比較・等値/大小比較・同一性・ビット演算・フォールバック・ベクトル積の候補を追加した。
再代入は構造メニューで演算子と nil 確認を変更できる。複合代入の解析時に生成された二項式は演算式メニューの対象から除き、書かれた右辺だけを編集する。
等値比較の候補は L^ の `=` に修正。`fits^` と `as^` は共通の式メニューから作成できる。右辺を値の式として扱わず型として表示し、既存の型構造メニューで基本型・名前付き型・配列型・nullable 型へ変更できる。演算子メニューで判定と変換を切り替えても左辺の値と右辺の型を保ち、式全体の置換もできる。実サーバーとブラウザーで作成・型変更・切り替え・置換後の再表示を検証した。

関連: `src/graphLists.ts` の `operatorSites`、
`src/webview/operatorExpression.ts`

## 9. モジュール情報・コメントの編集

- [x] module / import / require のモジュール名・読み込み先などを編集できるようにする。
- [x] コメント本文を編集できるようにする。

モジュール名・読み込み先とコメント本文をインライン入力で編集する。Enter / フォーカス離脱で未保存テキストへ反映し、Escape でキャンセル。

## 10. アノテーションの表示・編集（実装済み）

- [x] 付与先の左横の1つのボックスに、アノテーションを一覧表示する。
- [x] ドロップダウンでの追加・名前変更と、各行での削除に対応する。
- [x] 引数ごとの入力ノードで値の変更に対応する。数値・文字列は共通の入力部品を使う。
- [x] 一覧単位の折りたたみとドリルダウンに対応する。
- [x] ソースを変更せず空のボックスを一時表示し、その中の ＋ から最初の1件を追加できる。

言語の `@名前(引数)` が対象で、型注釈とは別の機能。
言語仕様上、引数はリテラルまたは名前に限られ、式は受け付けない。
現行サーバーが AST 応答に載せないアノテーションは、ソースの字句と宣言位置から補う。
先頭のアノテーションは言語仕様上「単位」に付くため、最初の宣言への追加ボタンは出さない。

## 共通化・実装の優先順案

1. **値・式の共通編集**: リテラルのソース反映、真偽値切替、参照先変更、式の置換・組み立て。
2. **要素の共通追加・削除**: 文、引数、メンバ、分岐の枝、ループ節など。
3. **構文固有の設定**: ループ形式、修飾子、読み込み先など。既存の書式編集も共通UIとの整合を保つ。

特に「穴やインライン値を別の式へ変更する共通の入口」を先に整えると、
構文ごとに専用の編集処理を増やさず、多くの編集箇所をまとめて対応できる。

## 網羅性の確認タスク

`testing/` 直下の16ファイルを実サーバーで解析し、使用される AST の種類を照合した。
式メニューにテーブル定義・自身のテーブル・条件式・補間文字列・`try^`・`pack^` を追加。
実サーバーによる再解析後も、式全体の置換と内部の値の編集が継続できることを検証した。
エラー値の作成、種別の参照先変更、ペイロード追加・編集にも対応。種別の欄では通常の値や呼び出しへの置換を許可しない。
宣言の公開・非公開、let / var の変更、def 内の abstract / override / overload と演算子メンバーの変更を構造メニューへ追加。
def の要素追加から型付き・抽象・演算子メンバーと self テーブルも作成できる。
列挙型・エラー定義・エラー種別・列挙メンバーの名前は既存のリネーム欄で編集する。
列挙メンバーは構造メニューで値の指定と自動採番を切り替える。
既定値のない引数は基本型へ変更できる。値を持つ宣言・既定値付きの引数は引き続きサーバーの互換候補で選択する。
明示した型には右クリックの構造編集を追加。同じ文書のスコープ内の型名、配列型、nil を許す型も作成できる。
ローカルな値を束縛してから条件を判定する `for^let^... if^...` も文追加から作成する。判定式を二重に描かず、焦点から分岐への実行線をつなぐ。
テーブルの名前付きキーも既存のリネーム欄で編集する。
この集計はサンプルの UI 再構築や AST 一致を証明するものではない。

### サンプルの再構築検証

`tests/graph-svg-browser.test.cjs` の `debug-fault sample` テストは、空の文書からコメント・変数・panic 文を UI で追加し、名前と値を入力する。
編集メッセージは `graphStatementEditor` / `graphRename` に渡し、実サーバーのリネームと再解析を利用する。
`testing/debug-fault.lh` と、位置情報・型検査由来情報を除いた AST（コメントと葉の内容を含む）が一致することを確認した。
AST 応答には演算子・修飾子がすべて格納されないため、字句列も別途比較する。冗長な括弧と末尾カンマは一致判定から除く。
コメントは区切りと外周の余白を除いた内容を比較する。行コメント・ブロックコメントの区別と内容は保つ。
同じ分岐を表す `else^` / `el^` は同一視する。補間内の式も字句比較の対象にし、括弧・空白を除いた演算子・値の違いは検出する。
文を既存の宣言の前へ追加するときは、付随するコメント・アノテーションの前に挿入して付与先を保つ。
空の中間分岐では、次の枝を指すことがあるパーサーの本体範囲ではなく、分岐ヘッダーの末尾へ挿入する。
この検証で見つかった panic 引数の固定ラベル表示を修正し、編集可能な子ノードとして表示する。
同じ方法で `debug-breakpoints.lh`（ループ内への代入、参照先、計算式、戻り値）、
`reference-library.lh`（モジュール宣言と公開定義）、`enum.lh`（自動採番と明示値、テーブル値）も UI 再構築と一致検証を追加した。
`references.lh` は require の別名、型付き引数、ローカル名、名前付きテーブル要素と参照先の構築も検証した。
`localization.lh` は日本語名・精密な数値の表記・改行文字列と明示的な型、
`returns.lh` は比較分岐・空の return・暗黙の戻り値・20個の戻り値を検証した。`empty.lh` はソースを変更せず最初の文の追加入口が使えることを確認した。
`literals.lh` は raw 表記・入れ子の定義・ペイロードの既定値・補間文字列、
`member-definitions.lh` は文字列キー・型付き self テーブル・抽象メンバー・コンストラクター・レシーバーと演算子メンバーも検証した。
この検証で見つかった括弧付きの位置要素が固定ラベルになる問題を修正。式の入力欄を保ち、削除・コメントの付与先には元の要素全体の範囲を使う。
複数束縛の右辺全体を1つの呼び出しへ変更する入口と、並列代入への名前・値の同時追加も対応した。
呼び出しの初期引数は現在の解析結果のシグネチャから作成し、引数なしの関数には余分な値を渡さない。
シグネチャが未解決の呼び出しも引数を追加・削除できる。確定した固定引数の個数制約は保つ。
オーバーロードでは呼び出し先の交差型から別のシグネチャも照合する。`slice^(開始)` から `slice^(開始, 終了)` へ引数を増やせる。
戻り値リストへの追加は括弧の内側へ行い、暗黙の複数戻り値への切り替えでも値の個数を保つ。
`multiple-returns.lh` 全体も、複数戻り値、引数付き呼び出し、条件式、エラーの伝播・捕捉、並列代入をUIから構築して一致を確認した。
`loops.lh` は無限・回数指定・while/until・範囲の各形式、各節・初期化・更新処理と本体のコメントを含めて一致を確認した。
`patterns.lh` は名前付きの焦点、文字列の複数候補、範囲と数値の混在、型パターン、文・式の分岐をUIから構築して一致を確認した。
`dispatch.lh` は無効化した列挙定義、入れ子の条件分岐、Unicode の比較演算子、補間文字列、名前付き型と nullable 型を含めて、UIからの再構築と一致を確認した。
`zero-based-indices.lh` は数値メンバー・添字・配列型・範囲とイテレーター・可変長引数・列挙定義・with の束縛・コールバックと複数の補間要素も含めて、空の文書からのUI再構築と一致を確認した。
`inventory.lh` はコンストラクター・レシーバー・演算子メンバー・焦点付き条件分岐・エラー定義と値・配列型・入れ子のテーブル・公開 main を含めて一致を確認した。これで `testing/` の16題材すべてに空の文書からのUI再構築・一致検証がある。
